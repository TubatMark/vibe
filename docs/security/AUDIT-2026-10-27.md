# Code and security audit

27 October 2026. A read of the whole tree (~3,900 lines across `convex/`, `src/`
and config) followed by a round of fixes. Nothing was deployed and no records
were deleted. Lint, TypeScript, the 18 regression tests, the production build
and `pnpm audit --prod` all pass on the result; the content policy was checked
in a real browser against `next start`.

## The one that mattered

**Host rights rode on a published id.** Every host-only mutation took
`userId: v.string()` from the browser and compared it with `room.hostId`, and
`rooms.getBySlug` returned `hostId` to everyone in the room. A browser can call
any Convex mutation directly, so a listener could read the host's id out of the
room and then play, pause, seek, skip, reorder the queue, approve or reject
requests, change the room's mode, or delete anyone's track. Room codes were six
characters (~30 bits), so the rooms to do it to could also be found by guessing.

Host rights are now a **host token**: 32 random bytes made in the creator's
browser with `crypto.getRandomValues`, stored on the room, sent with host-only
mutations, and never returned by any query. `getBySlug` names the fields it
publishes one by one, so a field added to the schema later is not published by
accident. `hostId` stays as the public Host badge and grants nothing. Room codes
are now ten characters (~50 bits).

This keeps the product's promise — no account, no email — but it is **hardening,
not authentication**. The token is a bearer secret in one browser's
localStorage: clearing storage or switching device loses the room, and anyone
who obtains the token is the host. Real accounts (Convex Auth) remain the answer
if rooms ever hold anything worth protecting.

## Also fixed

- **Nothing checked the track a client stored.** `queue.add` wrote whatever
  metadata the browser sent; the resolver actions were a convenience, not a
  guarantee. `thumbnail` went straight into an `<img src>` in every listener's
  browser, so any URL there was a tracking beacon for the whole room. Track ids
  are now checked against their source's shape, artwork must be https on the
  providers' own CDNs, and titles, artists, display names and room names are
  length-capped server side.
- **Any listener could skip the music.** `rooms.ended` advanced the queue for
  anyone who named the current track. It still cannot require the host token —
  whichever browser notices the end reports it — but it now ignores reports a
  paused room or a track less than five seconds in could not have produced.
- **Link hosts were matched by suffix.** `hostname.endsWith("youtube.com")` also
  matches `notyoutube.com`. Both parsers now compare whole labels, reject
  non-http(s) URLs, and validate the id before returning it. The YouTube id is
  URL-encoded into the oEmbed request, so it can no longer add parameters of its
  own.
- **No security response headers at all.** Added CSP, `Referrer-Policy`,
  `X-Content-Type-Options`, `X-Frame-Options`, `Permissions-Policy` and
  `Cross-Origin-Opener-Policy`. The CSP keeps `script-src 'unsafe-inline'`: the
  app is prerendered and partially prefetched, Next's bootstrap scripts are
  inline, and the alternative is a per-request nonce that would make every route
  dynamic — and a nonce or hash silently voids `'unsafe-inline'` for everything
  else. So it is **not an anti-XSS wall**. What it buys is a closed list of
  origins a page may load code from and, while a six-month Spotify refresh token
  sits in localStorage, a closed list of places it may send anything to.
- **A malformed saved Spotify session crashed the room.** `session?.profile.product`
  only guarded `session`, and localStorage outlives any one build. Sessions are
  now validated on read.
- **Decided requests were never deleted,** only marked, though only `pending` is
  ever queried. They are now removed.
- Parsing was duplicated between `convex/` and `src/lib/` and free to drift; it
  now lives in `convex/trackId.ts` and the browser imports it. `typecheck` and
  `test` are now package scripts.

## Follow-up: rate limiting and retention

Done in a second pass, on branch `security/convex-limits`.

**Rate limiting** now covers `rooms.create`, `queue.add` and `messages.send`,
via the `@convex-dev/rate-limiter` component; the limits live in
`convex/limits.ts`. What a key can be is decided by what the room actually
knows. A guest id is a random string the browser made up and can remake for
free, so a per-guest limit is a courtesy that keeps honest clients in line and
stops nobody who is trying. The limits that bind are keyed by the room — a row
nobody can mint — plus one global cap on room creation, which is what bounds
how fast the database can grow. The numbers sit far above a real room: ten
people adding songs and talking over each other will not meet them.

`presence.heartbeat` is deliberately not rate limited. It now refuses to write
the same row twice within five seconds, so a beat loop costs one indexed read
and nothing else — the structure does the job a limiter would.

**Retention.** Two crons in `convex/crons.ts`. Stale presence rows are swept
every five minutes; rooms idle for thirty days are deleted with all their
queue, request, presence and message rows, in budgeted batches so a large room
can never build a transaction too big to commit. `lastActiveAt` was written but
never read; it is now the idle signal, refreshed by playback, tracks, messages
and simply being present, at most once every five minutes so that a room full
of listeners is not also the app's busiest write.

**Presence write amplification** is fixed by removing the sweep from the
heartbeat path. It used to read and write the whole room's presence on every
beat, which is N² work per interval for N listeners, to delete rows `list`
already ignored. The cron sweeps `by_last_seen` across every room at once, and
a beat is back to one lookup and one write.

## Known and not fixed

- **Guests still identify themselves by a published id.** Removing your own
  queued track trusts `addedBy`, and chat and presence trust the name sent. One
  listener can act as another *within a room they are already in*. Fixing it
  properly means per-guest credentials, which means accounts. The same fact is
  why per-guest rate limits above are a courtesy rather than a defence.
- **`serverNow` comes from a cached query.** Convex warns against `Date.now()`
  in a query; the clock offset clients compute from it can be stale. Already
  noted in `docs/improvements/README.md`; left alone because it needs real
  playback to verify.
- **The Spotify refresh token is in localStorage** for six months, with
  `user-read-email` and playback scopes. PKCE in a static page is Spotify's own
  recommendation and the file says so, but it does mean XSS costs a Spotify
  account, which is why connect-src matters above.
- A room created when the browser dies before the token is saved has no host.

## Deploying this

The Convex argument shapes changed, so **the functions and the frontend have to
ship together**. `npx convex codegen` validated the schema, indexes, crons and
the rate limiter component against the deployment, but nothing was pushed: run
`npx convex dev` (or `npx convex deploy`) before or with the frontend, or room
controls will fail on `ArgumentValidationError`. `hostToken` is optional in the
schema so the push is not a breaking migration, but **rooms created before it
have no host** and their playback controls will no longer respond.

Two things start happening the moment the follow-up is deployed. The
`@convex-dev/rate-limiter` component is installed on the deployment as part of
the push. And the retention crons begin running: the presence sweep is
harmless, but **`prune idle rooms` deletes rooms, permanently**, so check the
thirty-day window in `convex/retention.ts` is the one you want first. No room
in this deployment is old enough to be caught by the first run.

Verified here: lint, types, 18 regression tests, production build, dependency
audit, and a browser pass over the home and room pages against `next start`
confirming the policy loads the YouTube embed and the Convex WebSocket with no
violations. Not verified: real Spotify playback (unconfigured here), the
deployed backend, and multi-listener behaviour.
